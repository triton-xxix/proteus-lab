# S-03: Memory and the assistant: auto-dream memory, the 27-minute executive assistant
## What it teaches
- Auto dream: a background sub-agent periodically reads recent sessions and the existing memory files, then merges, prunes and compacts them. MEMORY.md is kept as a short index with one-line links, not a dump.
- It only touches markdown memory files, never code. Triggers are probably time-based (about every 12 hours) or session-count-based (about 300), but the presenter says this is unconfirmed. It is toggled under /memory.
- Executive assistant: a folder is the home, CLAUDE.md is a short pointer file (under about 150 lines) that sends Claude to me/work/team/priorities files, rules, decisions log, projects and references. Skills do work in the main context; sub-agents get fresh context and can run a cheaper model (Haiku). Skills and agents need YAML front matter. Reports are saved to files so the state survives a cleared context.
- Growth loop: use it daily, log decisions, turn recurring tasks into skills, keep it in git.

## Tools they use
- Claude Code (VS Code extension), CLAUDE.md, skills, sub-agents, plan mode, /memory and auto dream.
- Perplexity API (Sonar model) for a research skill, key in a .env file. No URL named.
- ClickUp, Asana or Notion for task data. No URL named.
- Local git for version control, optionally GitHub.
- Presenter's free Skool community for the setup prompt. No URL named.

## What Proteus already has that does the same job
- Memory: Proteus already has a MEMORY.md index with one-line links and typed memory files, plus a consolidate-memory skill that does the same merge/prune pass by hand on request. Nothing runs it on a schedule, which is the only gap.
- Assistant scaffold: CLAUDE.md and CHARTER.md pointer files, PERSONA.md, BACKLOG.md, state/runs logs, and the vault mirror. This is the same home/life/hands/grow pattern, already further along.
- Sub-agents with model choice: the Sonnet reading children and the harvester's Sonnet judge. Scheduled tasks and the PreToolUse hook cover the unattended side, which the video does not touch.
- Git history as the version control and proof of timing.

## What we would need to fetch
Nothing. Auto dream is a built-in Claude Code feature, and anything Proteus wants from it can be done with the existing consolidate-memory skill. Perplexity is paid and keyed, so skip it.

## One thing worth trying

In /Users/triton/PROTEUS/sandbox/, copy the memory directory (MEMORY.md plus its linked files) into sandbox/memory-copy/, then run the consolidate-memory skill against the copy only and diff the result against the original. Measure: lines removed, duplicates merged, anything stale it flags, and whether any fact was lost. No accounts, keys or spend. Size: small, about 20 minutes. If the diff is clean, propose a weekly scheduled pass with the copy-and-diff step kept in, so Luke-facing memory is never overwritten unseen.
