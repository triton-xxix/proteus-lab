# S-13: Voice agents 3: LiveKit builder guide, and a voice agent that took every call for two years

## What it teaches
- LiveKit is an open-source real-time audio/video framework (code only until now). Its new Cloud agent builder is a no-code front end: pick STT, LLM and TTS providers, write a prompt, add HTTP tools, buy a number. It exports as a Python agent.py you can self-host, which is the point: you control call concurrency and cost.
- Reviewer's verdict: sounds and lags much like Vapi or Retell, has fewer controls and no prebuilt tools (booking, make.com, n8n), so it suits developers with time to maintain servers, not agencies.
- The two-year case (inbound property-management receptionist, built on Retell): the whole knowledge base sits inside the prompt, not in a RAG store, because retrieval returns only a few chunks and misses things. Works only while the facts are small.
- The prompt is persona, skills, knowledge, a growing "rules" list, then numbered steps per call type. Each new client request becomes a line in the rules, not a new flow. Monthly maintenance.
- Reliability trick: no live function calls except end call and transfer. Routing happens after the call: Retell's post-call extraction labels a "call reason" from the transcript, a webhook sends it to make.com, which branches and emails the right person. Keeps the live agent simple.

## Tools they use
- LiveKit (open source framework) and LiveKit Cloud agent builder: https://livekit.io (named in speech only)
- Retell AI (the production agent), Vapi (comparison): named, no URL given
- make.com (post-call automation with webhook and conditional routing), Google Sheets (call log), OpenAI module (phone number formatting only)
- Providers listed in the LiveKit builder: Cartesia, ElevenLabs, Rime, Inworld (TTS); Deepgram, AssemblyAI, Cartesia (STT); OpenAI, Gemini, DeepSeek (LLM); Twilio via custom SIP trunk

## What we would need to fetch
- Free and local: livekit-agents Python package and livekit-server (open-source, github.com/livekit) to run an agent on this Mac with local or keyless models. A phone line would need a SIP trunk or Twilio number, which costs money, so skip that.
- For the prompt-versus-retrieval test: Ollama is already here; nothing else.

## One thing worth trying
Test the "put it in the prompt, not RAG" claim without any voice at all. In /Users/triton/PROTEUS/sandbox/ make a fake 20-property fact sheet (about 3k words), write 30 caller questions with known answers (including awkward ones such as "which have lifeguarded pools and take pets"), and ask a local Ollama model each question two ways: whole sheet in the prompt, versus top-3 keyword or embedding chunks. Score by exact fact match. Size: small, about 25 minutes, no accounts, keys or spend. Caveat: a small local model may fail long context for its own reasons, so note the model and context length.

## Claims to check
- "486 hours saved over the past 2 years": check arithmetic. 486 h over 720 days is 40 min a day, above their own stated 30 to 40 minutes, and the figure ignores time the agent still costs (transfers, emergencies). Pure desk check.
- "roughly 2.5,000 calls over the past 2 years": 3 to 4 per day over 720 days gives 2,160 to 2,880, so it fits; but the saving per call then works out near 11.7 minutes against a stated 1 to 5 minute call. Desk check.
- "if you can put in the prompt it is going to be more accurate": run the sandbox test above.

## Verdict
PARK: LiveKit adds nothing we can use without a phone line or spend, and the review itself says it is not clearly better; the prompt-versus-retrieval test is cheap and the post-call routing idea is worth keeping in mind if the shelved receptionist demo (H-0085) is ever picked up.
