# S-20: Automatable: I Replaced n8n With Claude Code, 8 Things Your App Needs, Write Exactly Like You

## What it teaches
- n8n video (32 min): plan first with a CLAUDE.md and a project specs file, then one prompt per job. Claude Code wrote Python that read about 42 invoice PDFs, extracted text with the Anthropic API, renamed and sorted them by month, flagged duplicates, pushed rows to Airtable, and built a summary plus an HTML dashboard. Errors were fixed by the agent inside one prompt. The host says to deploy to modal.com, trigger.dev, replit or render to run it unattended.
- 8 things (28 min): a prompt-by-prompt SaaS build with Supabase (database, auth, per-user row isolation), Stripe in test mode (checkout, webhook that flips the plan, customer portal, lock-out after two failed payments), then GitHub and Vercel with keys in environment variables. The pattern is that Claude writes SQL, the human pastes it into the Supabase editor and copies keys by hand.
- Write Exactly Like You (12 min): seven markdown files (who you are, beliefs, tone, vocabulary, humour, stories, analogies) filled automatically from the last 100 emails, 25 meeting transcripts, a LinkedIn post and a humour passage, via Gmail and Fireflies connectors. Then a slash-command skill that reads those files plus an example post structure. The vocabulary file also lists words never used, such as "henceforth".
- Nothing here is a new mechanism: all three are the CLAUDE.md, plan, one-prompt-build loop S-07 and S-14 already covered.

## What Proteus already has that does the same job
- Invoice sort, rename, CSV, dashboard: nothing directly (Proteus has no invoices), but the pattern is covered by `bin/` Python scripts, the static `docs/` site and HyperFrames for output. PDF text extraction can be done locally (pdftotext or a Python library) without the API.
- Unattended deployment: scheduled tasks, launchd pollers and the PreToolUse hook, which keep the agent in the loop and are stricter than a cloud host.
- SaaS stack (Supabase, Stripe, Vercel): nothing, and not wanted. It needs accounts and keys, and Proteus does not sell software.
- Voice files plus a skill: PERSONA.md and the voice rules in CLAUDE.md, with Claude Code skills. S-18 already noted the missing piece is a mechanical banned-words check. The new part here is the idea of building the voice profile from real past writing rather than an interview, and the "words I never say" list.

## One thing worth trying
A "voice from evidence" profile of Proteus's own writing, in /Users/triton/PROTEUS/sandbox/. Stdlib Python, about 40 lines: read the last ten finished Field Notes and run logs, count word and phrase frequencies, list the top 50 non-stopword terms, sentence length spread, and any opener phrases that repeat three times or more. The aim is to see whether Proteus drifts towards repeated stock phrases, which is the "sum of the average" problem the third video describes. Different from S-18's banned-words lint: this measures what Proteus does say rather than checking a fixed list. Size: small, about 20 minutes, no keys, no spend. Low value though, because Proteus has a short, strict voice guide already and a lint script would probably find the same things. Rest of the videos: no test worth running.
