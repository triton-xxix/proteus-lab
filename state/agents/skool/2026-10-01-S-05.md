# S-05: Paperclip
## What it teaches
Multi-agent orchestration around a shared business model. Agents wake on heartbeats (schedules), read ticketed tasks and their company state, and continue work. A central dashboard shows all agents, tasks, approvals and per-agent spend. Agents can propose to hire other agents (recursively). Routines define recurring workflows. Pre-built company templates (GStack, agency orgs) let you import a whole team in one click.

## Tools they use
Paperclip, open-source agent orchestrator: https://github.com (full URL not named in transcript, but trending on GitHub with 36,000 stars as of March 2026)
Claude Code (or Open Claude or Cursor)
GitHub, for skills and company templates
skills.sh marketplace for pre-built agent skills
Local or VPS host (local by default)

## What Proteus already has that does the same job
Claude Code with scheduled sub-agents and the PreToolUse hook (heartbeats via launchd pollers or scheduled-tasks runner). State tracking via MEMORY.md, CHARTER.md, state/runs logs (ticketing equivalent). Skills registry. Budget and call caps enforced at the hook. No visual dashboard, but run logs are readable.

## What we would need to fetch
Paperclip repo (free, MIT, open source). Optional: a skills repository or pre-built company template from Paperclip's catalog. Optional: a VPS to host it (not needed for mechanism test).

## One thing worth trying
Local Paperclip two-agent company with CEO self-hire attempt. In /Users/triton/PROTEUS/sandbox/, clone Paperclip (npm install, npm run), set up a CEO agent with heartbeat every four hours, give it the task "hire a founding engineer", check whether the approval UI or state management reveals governance patterns Proteus doesn't have. Measure: time to setup, whether the CEO's self-hire request is logged in a queryable way, what state the dashboard shows vs what a run log shows. Size: medium, 30-40 minutes, needs Node and npm only.

## Verdict
TRY The mechanism (heartbeat, ticketing, recursive hiring) solves the "30 terminals" pain point Proteus might face and teaches about agent autonomy and governance at scale. Open source, no accounts or keys. The question is whether a visual dashboard plus self-hiring plus per-agent budgets add enough to Proteus's hook-based governance to change how it schedules work. A 30-minute local test would answer that.
