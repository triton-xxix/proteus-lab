# S-04: Deploy and pull: Trigger.dev, Firecrawl MCP, self-healing n8n

## What it teaches
- Trigger.dev: Claude Code writes TypeScript tasks (scheduled pollers plus agent tasks), a hosted runner executes them with cron, retries, queues and a live run log. Dev mode needs your laptop connected; production deploys on a GitHub push. Secrets go into the runner's env vars, not git.
- Firecrawl MCP: one MCP server wraps scrape, map, crawl, search and extract. Claude picks the endpoint, and falls back (scrape, then map, then extract, then its agent) when one returns empty. Output is markdown, screenshots, branding, JSON.
- Self-healing n8n: a workflow's error trigger fires an HTTP call through an ngrok tunnel to a local server, which starts Claude Code with the failed workflow ID and error. Claude fixes it through the n8n MCP and skills, then posts to ClickUp. Auth, outage and rate-limit failures get "user action required" instead.
- Common thread: a CLAUDE.md plus a cheat sheet or reference file steers the agent, and failures are routed back to an agent.

## What Proteus already has that does the same job
- Scheduled, retried jobs: launchd pollers and the scheduled-tasks runner, with state/runs logs. No cloud, no per-run UI beyond the logs.
- Agent loops with tools: Claude Code sub-agents and skills, under the PreToolUse hook (the hook is stricter than anything shown here).
- Scraping and pulling: keyless YouTube, HN, GitHub and arXiv pulls, plus the harvester. The toolshelf has Playwright (T-0015) for headless Chromium, which covers the JS-rendered pages Firecrawl sells.
- Self-healing: nothing automatic. Failed runs are read by the next nightly run and logged. The nearest thing is the denial-and-route-around rule in the hook.
- Cost and dedupe: the audit and probe caps cover the "bounded spend" side.

## One thing worth trying
Local "heal on fail" loop, no accounts. In /Users/triton/PROTEUS/sandbox/ make a tiny puller script with a seeded bug (for example it expects a list but gets a dict, or a null field). Wrap it in a runner that, on non-zero exit, writes a failure packet (script path, stderr, last input) to a file and spawns a Claude Code child with a fix-only brief and an allowlist of that one file. Add the rule from the n8n video: classify failures as fixable (logic, data shape, typo) or human-needed (expired key, API down, rate limit) and only attempt the first. Run it against five seeded faults, three fixable and two not. Measure: fixed correctly, correctly refused, and tokens used. Size: small, about 25 minutes, one script and one prompt. Note that the child needs permission under the hook, and a refusal is itself the result to log.

## Claims to check
- "25 leads created in nine seconds across five cities." Rerun a fan-out of 25 small tasks locally with a timer; hosted-queue speed is not reproducible without an account, so only the local equivalent is checkable.
- "that took me about 30 credits out of my 500." Only checkable with a Firecrawl key; compare against a Playwright fetch of the same three pages for equivalent output, free.
- "set up in 30 minutes to an hour." Check by timing the local heal-loop test above, which is the keyless slice of it.

## Verdict
PARK The mechanisms are sound and mostly duplicate what Proteus has, but the heal-on-fail loop is worth a sandbox test later; the hosted tools add accounts and keys for no new capability.
