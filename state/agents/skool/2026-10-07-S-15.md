# S-15: AIS: Stop learning n8n, build n8n flows with CC, build anything with n8n and CC

Three videos from the same host (about 18, 28 and 40 minutes). The "argument" is soft: video one says n8n is "not dead, just the foundation", videos two and three use Claude Code to drive n8n, not replace it.

## What it teaches
- Video one (Stop learning n8n): describe the outcome in plain English and Claude Code writes TypeScript tasks run by a hosted runner (Trigger.dev), with ClickUp as the inbox and outbox. Demos: an AI-news YouTube check every 8 hours with dedupe on video ID, a company-research agent woken by a new ClickUp task, and a LinkedIn post plus infographic agent (search, read URL, finish tools; polls an image API until done). Failure modes named: context drift, hallucinated APIs, over or under-engineering, and no dashboard unless you build observability.
- Video two (build n8n flows with CC): a CLAUDE.md, an n8n MCP server (node docs, templates, create and update workflows through the n8n API) and seven n8n "skills" (expression syntax, patterns, validation, node config, JS and Python code). Plan mode first, then bypass permissions, and the agent builds a workflow in a live n8n cloud instance and fixes its own node errors. It got two model settings wrong (GPT-4.1 instead of GPT-5, Sonnet 4 instead of 4.5).
- Video three (build anything): Claude Code audits an existing n8n workflow for web use (form trigger to webhook, base64 file input, a JSON reply the front end can show, error branches), builds a front end, pushes to GitHub and deploys on Vercel. Its first deploy failed on a missing env variable, so the host hard-coded the webhook URL.
- The honest limit, said in video two: asking for a 60-node workflow throttled his n8n cloud and it stayed down over an hour (error 522).
- Mechanism in one line: an agent plus a doc-search tool plus a write API for the target system, with the human pasting keys and fixing credentials.

## Tools they use
- Claude Code in VS Code (extension), plan mode and bypass permissions. No URL.
- n8n cloud, and the n8n MCP server plus n8n skills, both GitHub repos by one author (the same person who built both). Repo URLs are only in the description; none spoken.
- Trigger.dev, hosted task runner: trigger.dev (named). ClickUp as trigger and inbox. No URL.
- kie.ai (spoken "key.ai") for Nano Banana Pro images. No URL.
- OpenRouter, Perplexity, Gmail inside the built n8n workflow. No URLs.
- GitHub (fine-grained personal access token) and its MCP server; Vercel for deploy; Tailwind CSS; a front-end design skill. No URLs.
- Whisper-based dictation app ("whisper flow"). No URL.

## What Proteus already has that does the same job
- Plain-English build with plan mode, CLAUDE.md and a rules file: Proteus is that already, with CHARTER.md, the PreToolUse hook and HALT, which these videos lack (they run bypass permissions and put real keys in a project MCP file, which the host admits is a risk).
- Scheduled "new item since last time, summarise it": launchd pollers, the keyless YouTube, HN, GitHub and arXiv pulls, seen.py as the dedupe guard (same idea as the video-ID idempotency key), and the weekly Field Notes. Covered in S-14, S-19 and S-04; not repeated.
- Research agent woken by a task: the harvester (bin/harvest.py with one Sonnet child) and the probe loop, with a call cap and deadline, which the videos do not have.
- n8n itself: on the toolshelf as T-0043 (shelf, no probe). Nothing in Proteus needs it.
- Workflow-as-MCP-plus-skills: the toolshelf has other MCP servers (3d-asset-server T-0092, Breadcrumb T-0061) but no "write API plus node docs" pairing like this. The nearest local equivalent is Claude Code skills with a reference file.
- Image generation via polling API: nothing, and no desk needs it. HyperFrames covers video and static output.
- Front end plus GitHub plus Vercel: the static `docs/` site, no hosting service.

## What we would need to fetch
Nothing for the mechanism. For the exact stack: n8n (free self-host or cloud trial), the n8n MCP and n8n skills repos (free, GitHub), Trigger.dev (free tier, account), ClickUp, kie.ai, Vercel (accounts and keys). None serve a Proteus desk.

## One thing worth trying
None worth a slot. The only transferable piece is "ask the agent to audit an existing flow for failure paths before putting an interface on it", and Proteus has no n8n flows to audit. A keyless variant would be to take one `bin/` puller and ask a child to list its missing error branches, but that is plain code review and the harvester already gets that. Nothing here is a runnable under-30-minute test that tells us something new.

## Claims to check

## Verdict
SKIP: three beginner demos of the CLAUDE.md, plan mode and one-prompt loop Proteus already runs under stricter controls; the n8n MCP plus skills pairing is the only new idea and Proteus has no n8n flows to use it on.
