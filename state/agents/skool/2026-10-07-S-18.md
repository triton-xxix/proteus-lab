# S-18: Agent J 7-Day Challenge, Days 3-5 (text, Voice DNA video) and Day 7 (vibe-coded app, localhost to deployment)

Note on the two videos: both are recordings of live community Q&A calls, not scripted lessons. The "Day 5 Voice DNA" video is mostly a newcomer (Angie) debugging a skill install, then a tour of Cowork and a 100-question-interview pitch. The "Day 7" video is a beginner Claude Code session on the desktop app. Neither matches its title closely. Auto-captions are rough.

## What it teaches
- Day 3 and 4 (text): a skill is a saved prompt template (job, five rules, one example); automation is the runner, MCP the hands, skill the how-to. Same level as Days 1-2.
- Day 5: Voice DNA is a 100-question interview run by Claude (seven categories, one question at a time, push back on vague answers), compiled into a markdown profile. It is then paired with a banned-words list (90+ words) and a blocked-patterns list (9 structural AI tropes), and installed as a skill whose SKILL.md points at those files.
- Day 5 call: the install failed because the Desktop skill sandbox could only read SKILL.md, not sibling files. The fix on the call was to put the files in a mounted folder and reference them by path, so one edit updates every skill that cites them.
- Day 7: run a dev server on localhost, preview, then have Claude push to GitHub, and Netlify auto-deploys from main. Global CLAUDE.md rules: summarise your understanding and wait for approval, investigate before guessing, log what was done.
- Advice repeated: never let the AI send replies, only draft them; dump context into one folder so it is not siloed per chat.

## What Proteus already has that does the same job
- Skills with a SKILL.md and files beside them: Claude Code skills in Proteus already do this properly, and the scheduled-task and hook stack goes far past the Day 3 template.
- Voice profile: PERSONA.md and the "voice" rules in CLAUDE.md (plain English, UK spelling, no em dashes) already work as a short voice guide. There is no interview-built profile and no mechanical banned-words or blocked-patterns check. That is the one gap.
- Localhost preview and deploy: Proteus has docs/ as a static site and Claude Code with git. Netlify or Vercel is not used.
- Global CLAUDE.md "summarise and wait for approval" rule: Proteus does the opposite on purpose (autonomous, logged, hook-governed).
- Second-brain folder with a single context location: the vault mirror, memory directory and state/runs already do this.
- Whisper dictation: local whisper is there.
