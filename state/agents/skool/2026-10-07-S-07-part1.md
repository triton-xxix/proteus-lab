- 00:00 to 05:00: pitch and agenda. Three builds: a Willow-style video interview SaaS, a PDF bookkeeping automation, and a web app that triggers a backend agent workflow (TikTok viral scrape). Host is John (Automatable), who says he has a 350-person paid community.

- 29:00 to 38:00: Next.js and Tailwind scaffold, to-do list, build-passes check. Host swaps in his own pre-written "bulletproof" prompts to reduce run-to-run variation.
- 38:00 to 53:00: build the marketing site from a screenshot of willow.video, two errors fixed by pasting them back (missing Supabase keys, stale .next cache), queued messages, model and thinking switch.
- 53:00 to 63:03: wiring the contact form to Airtable through an MCP connection, token scopes, .env.local and .gitignore. Ends mid-setup at "add the MCP server".

## What it teaches that earlier digests do not
Almost nothing. It is the same WAT-style beginner pattern as S-02 and S-14: CLAUDE.md as the rules, plan first, to-do list, self-test, self-heal on pasted errors, bypass permissions. Small new bits, none of them useful to Proteus:
- The host's trick for repeatability: have Claude write "bulletproof" prompts and a project specs file after a good first build, so viewers can replay them with less drift. A sensible idea, but Proteus already pins behaviour through CHARTER.md and committed predictions.
- Dev-server port clash: a second project silently showed the first project's site on port 3000. Trivial.
- Secrets in .env.local, kept out of git by .gitignore, with an .env.example stand-in. Standard, and Proteus already uses secrets.py.
- His MCP explanation is loose ("sending data from point A to point B"). It is not a mechanism description.
