# S-08: Brendan: How To Build Agentic Workflows, 5 Claude Skills I Can't Live Without

## What it teaches
Video 1 (agentic workflows): replace an n8n drag-and-drop flow with plain code that Claude Code writes, deploys to an always-on host (Railway, via its MCP server) and debugs from logs. Example is a calendar-booking webhook that must reply synchronously to a voice agent.
Video 2 (5 skills): a skill is a markdown file of instructions. Install by pasting a GitHub URL into Claude Code and saying "install this skill", or by dropping in a zip from a skill marketplace.
The five: humanizer (voice sample plus an AI-slop pattern list), architecture diagram creator, Remotion (video from code), front-end design, PDF generation.
The only real mechanism is "code instead of nodes, host it, let the agent read the logs". The rest is install-by-URL.

- Claude Code: the agent that writes and deploys everything.
- Railway (no URL named; the host, with an MCP server and a $5 a month plan).

- Architecture diagram creator skill from MCP Market (no URL named).

## What we would need to fetch
Nothing. Railway would only matter if a public webhook with a synchronous reply were wanted, and that costs money and an account. The skills are markdown files Proteus can already imitate.

## One thing worth trying
A stdlib-only Python webhook in /Users/triton/PROTEUS/sandbox/ that takes a booking JSON POST, checks a made-up availability list and replies in the same HTTP response, with request logging to a file. Then curl it on localhost. This tests the one real claim, that a code-first workflow gives the synchronous answer that trigger.dev would not. It is small (about 40 lines, 15 minutes), needs no account, key or spend. Expected result: it works trivially, which is itself the finding that the idea is not hard.
