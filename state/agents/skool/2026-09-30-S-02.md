# S-02: Claude Code core: the 95 percent masterclass, skills beginner to pro, skill-creator update

## What it teaches
- WAT layout: a CLAUDE.md as project system prompt, markdown workflow files as SOPs, and Python tool files the agent runs. Plan mode first, then build, test, and let the agent fix its own errors and update the workflow.
- A skill is a folder with SKILL.md (YAML name and description, then steps) plus optional scripts and references. Loaded in three levels: front matter only (about 100 tokens), full file on a match (1,000 to a few thousand), extra files only if needed. Keep SKILL.md under 500 lines.
- Skill habits: build from a run you just did, watch the first runs, hard-code lookups the agent keeps redoing (list IDs), delegate heavy searches to a sub-agent, add a rule for a repeated mistake. Front matter can also set allowed tools, model, hooks, agent and disable-model-invocation.
- skill-creator update: two skill kinds (capability uplift, which may become redundant as models improve, and encoded preference, which stays durable), plus evals, with/without-skill benchmarks (pass rate, time, tokens), regression and outgrowth checks, and description tuning for false triggers.
- Deployment is Modal (cron or webhook) with secrets in .env or Modal secrets. The agent stays local, so deployed runs do not self-heal.

## What Proteus already has that does the same job
- CLAUDE.md plus CHARTER.md as system prompt and rules; BACKLOG.md and state/runs as the self-documenting loop.
- Skills and sub-agents in Claude Code, including the "delegate the noisy search" pattern (these reading children, the harvester's Sonnet judge).
- Scheduled tasks with the PreToolUse hook: stricter than Modal for our purposes, and the agent does run inside the deployment, which the video says Modal cannot do.
- Keyless YouTube, HN, GitHub and arXiv pulls replace the YouTube Data API plus quota-burning approach.
- Secrets handling via secrets.py and the 1Password SDK, which is what the video's .env advice is reaching for.
- Pre-registered commits and audit/recompute.js already do more than the video's "run it and eyeball it" testing.
- Nothing equivalent to skill evals or trigger tuning.

## One thing worth trying
A skill hygiene audit, about 10 minutes, in /Users/triton/PROTEUS/sandbox/: a read-only Python script that walks every SKILL.md in the repo and in ~/.claude/skills, and reports line count (against the 500 line advice), description length in words (rough token estimate against the "about 100 tokens" claim) and whether the description names concrete trigger phrases. No accounts, keys or spend. Tiny: one short script. Its output would show whether our live task prompts and skills are heavy or vague. A bigger follow-on, not for tonight: write 5 to 10 trigger prompts per skill and count correct firings, which is the trigger-tuning idea without the plugin.
