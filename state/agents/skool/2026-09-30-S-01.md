# S-01: Running Claude Code unattended: scheduled tasks, /loop, auto mode

## What it teaches
- Desktop scheduled tasks: a cron entry stored on disk fires a fresh, stateless session with a saved prompt, model, mode and folder. The Mac and app must be on. Missed runs from the last 7 days are caught up on wake.
- /loop uses CronCreate, CronList and CronDelete inside one live session. It dies when the session closes, expires after 3 days, has no catch-up, and grows context each fire.
- Suggested memory pattern: one status file per task, overwritten each run (last run, duration, known issues), read at the start and rewritten at the end. Preferred over an append log because logs bloat.
- Auto mode: a classifier reviews every tool call for destructive actions and prompt injection, blocks risky ones and lets the agent try another route. Costs slightly more per session. Presented as the middle path between ask-every-time and bypass permissions. It was a Team-plan research preview when recorded.
- Hooks are suggested for a "session finished" sound or a message. Unattended runs should be test-run once by hand so permission prompts do not stall them.

## What Proteus already has that does the same job
- Scheduled nightly runs: Proteus already has these, plus the wider stack of desks, probe loop and harvester.
- Permission control: the PreToolUse hook `.claude/hooks/unattended-decide.py` (allow on a safe list, deny everything else, never prompt) is stricter and more deterministic than auto mode's classifier. It also covers sub-agents, which the videos do not discuss.
- Memory between stateless runs: `state/runs/YYYY-MM-DD.md` and `state/probes.json`. The dated append log is the pattern the video argues against, but ours is one file per day, so it does not grow into one huge file.
- Stop switch: the `HALT` file. Nothing in the videos matches it.
- /loop: nothing needed. Nightly work is not session-bound, and the 3-day expiry makes it unsuitable.

## One thing worth trying
A gap check, about 10 minutes in `/Users/triton/PROTEUS/sandbox/`: read-only script listing the last 30 dates with no `state/runs/YYYY-MM-DD.md` file, or one under a few lines. This tests whether the video's catch-up gap (Mac asleep at fire time) has been silently costing us nights, which the run log alone does not tell us. Tiny: one short Python script, no accounts, keys or spend. Follow-on, only if gaps appear: add a "read yesterday's status file and note missed nights" line to the nightly prompt.
