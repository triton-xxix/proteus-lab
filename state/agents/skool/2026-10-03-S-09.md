# S-09: Scrapers 1: Automatable "This AI Agent Can Scrape ANYTHING", n8n + Apify
## What it teaches
- Two videos from the same creator. Both rent a ready-made scraper ("actor") from the Apify store and call it over plain HTTP from n8n.
- Call shape: POST to the actor's run endpoint with a bearer token and a JSON body (search term, location, max results). The run-sync form waits up to 300 seconds, then returns the dataset rows.
- Video 1 wraps that in a chat agent. A system prompt routes the user's request to one sub-workflow per source (Google Maps, Yellow Pages, Apollo, Instagram, TikTok). The model only fills in the industry, city, state and country.
- Video 2 chains two actors: Google Maps listings, then a contact-detail crawler over each listing's website (link depth 1, capped pages) to find an email. A loop with batch size 1 and an array aggregator stop it blowing the memory limit and duplicating rows.
- Output is appended to a Google Sheet, matched on a unique column. The end use is cold-email lead lists.

## Tools they use
- n8n, workflow automation, cloud or self-hosted (no URL named; it is already on the shelf as T-0043).
- Apify, the scraper marketplace and runner, free tier of $5 monthly credit (no URL named in the transcript).
- Apify "Google Maps Extractor" by Compass, charged per result (no URL named).
- An Apify Google Maps contact/email extractor (named loosely, no URL).
- Google Sheets append-or-update node.
- OpenAI chat model with window buffer memory as the agent brain.
- Instantly and Lemlist, mentioned only as cold-email destinations.

## What Proteus already has that does the same job
- Orchestration: Claude Code with skills, scheduled tasks, launchd pollers and sub-agents do everything n8n does here, and the PreToolUse hook governs it. Nothing to gain from n8n for orchestration.
- Fetching: the keyless YouTube, HN, GitHub and arXiv pulls and bin/harvest.py cover open sources.
- Storage: CSV and JSONL in the repo replace Google Sheets.
- What is genuinely missing: a way to read sites that block plain fetches or need a browser and proxies (Google Maps, Instagram, TikTok, Apollo). Nothing on the stack does that today. Those sources are also the ones with terms-of-service and privacy problems, and the stated use here is harvesting business contact details for cold email, which Proteus has no reason to do.

## What we would need to fetch
- Nothing now. The only new capability on offer is Apify's hosted actors, which need an account, an API token and metered spend. That fails the keyless, no-spend habit, and the charter's money rules would need an ask.
- If a blocked source ever matters to a desk, the free route is Playwright (already on the shelf as T-0015) against a single named site, not a marketplace.

## One thing worth trying
None worth running in sandbox/ tonight. Every real test needs an Apify account and token, and the no-account part (the HTTP call shape) is just a documented curl. Size if wanted later: trivial, about 10 minutes, but it needs a key.

## Claims to check
- "$6 per thousand results": check the actor's pricing page and the usage line on a five-result run, only if an account ever exists.
- "$5 which is a lot of results ... up to thousands": at $6 per thousand that is about 830 results, so "thousands" only holds for cheaper actors. Arithmetic check against the same pricing page.
- "wait for finish equals 300": the transcript says runs over 300 seconds fail. Check against Apify's API docs.

## Verdict
PARK: it is a tidy pattern for renting scrapers, but Proteus already orchestrates better, its open-data pulls need no key, and the new capability (blocked sites, lead scraping) costs money and sits badly with the charter.
