# S-14: AIS: Zero to your first CC workflow, $10K agentic workflows, watch my agents work

## What it teaches
- The "WAT" pattern: a CLAUDE.md tells Claude Code to keep Workflows (markdown SOPs), act as the Agent, and call Tools (small Python scripts) in separate folders.
- Plan mode first, answer its questions, then bypass permissions to build. Errors get fixed in the tool and written back into the workflow, so the same failure does not recur.
- Business facts and competitor data are saved to JSON files so later runs reuse them (caching and memory by file).
- Honest caveat in video two: self-healing only happens while the agent is present. Deployed to a scheduler (trigger.dev, Modal) you ship workflows and tools only, so it runs as ordinary deterministic automation.
- Video three is a VS Code extension (Pixel Agents) that draws Claude Code sessions and sub-agents as pixel characters by reading the session activity log. The rest of video two is sales advice: price on value, not hours.

## Tools they use
- Claude Code in VS Code, paid Claude plan, plan mode and bypass permissions mode (no URL named).
- Firecrawl for scraping, Perplexity for research, ReportLab and matplotlib for PDFs and charts (no URLs named).
- kie.ai (spoken as "key.ai") as a route to Nano Banana image generation (no URL named).
- Gmail and Google Sheets for sending and archiving a newsletter (no URL named).
- trigger.dev, Modal, Vercel for deploying workflows and tools on a schedule (no URLs named).
- Pixel Agents VS Code extension, by Pablo Deuca (extension search "pixel agents"; no URL named). Windows only at the time, and the folder name cannot contain a space or a full stop.
- Skills, including the front-end design skill (no URL named).

## What Proteus already has that does the same job
- WAT is what Proteus already is: CLAUDE.md and CHARTER.md as the rules, SKILL files as workflows, `bin/` scripts as tools, run logs in `state/runs/`, memory directory as the saved facts. Proteus goes further with a PreToolUse hook and a HALT file, which the videos lack.
- Scheduled runs: scheduled tasks plus launchd pollers, which is the deployed-without-an-agent split the second video describes, except Proteus keeps the agent in the loop.
- Competitor research and report: keyless HN, GitHub, arXiv and YouTube pulls, the harvester, and Field Notes. Branded output: HyperFrames and the static `docs/` site.
- Monitoring many agents: `state/runs/`, `state/agents/`, the decisions log, `bin/usage.py` and HOME.md. The toolshelf already holds agent-office (T-0003), tmux (T-0005) and coucou (T-0019) for the same "watch the agents" job. The Mac cannot run Pixel Agents anyway.
