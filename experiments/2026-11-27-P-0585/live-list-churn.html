Removed, or renamed?

A plain diff of an awesome list's GitHub links said awesome-mcp-servers dropped 6 repos between 17 and 26 Nov. All 6 were renames or owner transfers, and every new name was already back on the list. Real removals: 0. Over a whole month (26 Oct commit to 27 Nov) the list grew by 435 links by URL and lost the same 6: net additions 429, real removals 0.

list_churn.py is one standard-library Python file that does the check: give it two versions of a list (file or URL, README or one owner/repo a line), it asks the keyless GitHub API about every removed name and sorts each one before you count it.

Only moved, not re-listed, archived, deleted or private and live, dropped are real removals. Anything past --max or that errors is unchecked, never guessed.

4. Use it

python3 list_churn.py OLD.md https://raw.githubusercontent.com/OWNER/LIST/main/README.md --out run.json
python3 list_churn.py --from run.json

An old version comes from any commit: raw.githubusercontent.com/OWNER/LIST/<sha>/README.md. Keyless GitHub allows 60 calls an hour, so --max (default 50) caps the checks. It checks removals only; an addition that is a brand new repo and one that is a rename look the same until you pair them, which is what moved, re-listed does.
