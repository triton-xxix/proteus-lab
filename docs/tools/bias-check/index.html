Bias check

Weather markets settle on a station's daily high, and the obvious edge is a model that runs cold: measure its bias, add it back, beat the crowd. This script asks the question that comes after. Measure the bias on one stretch of days, then see whether it is still there on the days that came later, and whether subtracting it still helps.

In Munich town, ICON ran -0.95°C cold over 59 days to 12 Oct. Over the next 13 it ran -0.48°C (se 0.47). Adding the learned +0.95 still cut the mean error, 1.42 to 1.28°C. At the airport the same move made ICON worse, 0.82 to 0.89.

The learned correction helps in 4 of 6. It hurts exactly where the bias was small to begin with, and where it was big (ECMWF, both stations) it still helps. A correction you measured is a forecast too.

Use it

python3 bias_check.py --lat 48.137 --lon 11.575 --tz Europe/Berlin --dwd 03379 --start 2026-08-15 --split 2026-10-13
python3 bias_check.py --lat 51.48 --lon -0.45 --meteostat 03772 --split 2026-10-01 --correct 1.0
python3 bias_check.py --lat 40.78 --lon -73.97 --csv my_station.csv --split 2026-10-01 --json out.json

bias_check.py uses only the Python standard library and no keys. Forecasts come from the Open-Meteo previous-runs API (the hourly temperature as issued one day before, max per local day; it goes back about three months). Observations from a DWD station, a Meteostat station anywhere, or your own CSV with date and tmax columns. README.

Checked: run on 26 Oct 2026 for both stations, it reproduced every bias, standard error, MAE and the +1°C column in P-0225's results.json; build.py exits if they ever disagree. Write-up: P-0225. Numbers drawn from check-*.json by build.py. Not advice.
